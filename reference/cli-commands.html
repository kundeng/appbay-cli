CLI Command Reference

Every CLI command with flags, examples, and exit codes

Overview

The Appbay CLI is a single compiled binary built with Bun. It directly imports @appbay/core and operates entirely offline — it does not use a tRPC client or require the Appbay server to be running. Commands that deploy containers invoke docker compose directly.

Global flags

Flag Description
--help Show help for any command
--version Print CLI version
--server <url> Override server URL (default: http://localhost:3000)
--token <token> Override auth token (alternative to APPBAY_TOKEN env var)

Commands

appbay setup

The guided path, and the one most people should start with: it runs init, creates the secret vault, and brings up the edge, in order, asking only for what it cannot infer.

appbay setup --domain home.lan
appbay setup --domain example.com --email you@example.com --ingress-provider caddy --yes
appbay setup --status
Flag Default Description
--domain <domain> (prompted) Base domain for ingress routing
--project <name> (prompted) Project name
--email <email> (prompted) ACME email, for Let’s Encrypt certificates
--ingress-provider <p> traefik Edge to install: traefik or caddy
--yes false Non-interactive: accept all defaults
--status — Report what is already set up, and change nothing
--reset — Tear down system apps and remove generated configs

⚠️ The administrator setup creates is the edge administrator, which guards apps behind the reverse proxy — and since RFC-001 §1 that is the SAME account that signs in to the web control plane, which no longer has one of its own. It needs the authp/admin role to reach the control plane. See Credentials — the two are deliberately separate and are never synchronised.

Exit codes: 0 = success, 1 = a step failed.

appbay install

Install an app from the catalog into $APPBAY_HOME/etc/apps/<name>/.

appbay install jellyfin
appbay install nextcloud --set ADMIN_USER=me --set TZ=Europe/Berlin
appbay install adminer --as adminer-staging      # a second copy
Flag Default Description
--set <pairs...> — Input values as KEY=VALUE, repeatable
--as <name> the catalog name Install under a different app name
--force false Overwrite an app of the same name
--no-validate false Skip post-install validation

--as splits the catalog lookup from the install location, which is what makes a second copy possible: without it both were the same value, so installing an entry twice overwrote it.

⚠️ Not the same axis as namespace:. A namespace disambiguates two deployments of one installed app; --as gives you two installations, each with its own directory, manifest and config. Use --as when the copies should differ in what they are, namespace: when they differ only in where they run.

Installing copies the upstream files unmodified and writes an appbay.yaml beside them. Nothing is deployed until you run appbay up.

appbay catalog

Browse and manage catalog sources.

appbay catalog list
appbay catalog search media
appbay catalog info jellyfin
appbay catalog add-source https://github.com/you/your-catalog
appbay catalog update

appbay shell · appbay exec · appbay run

Reach into a running app.

appbay shell jellyfin                      # interactive shell in the service container
appbay exec jellyfin -- ls /config          # run a command in the running container
appbay run jellyfin -- /bin/backup.sh       # one-off command in a fresh container

shell and exec require the app to be running; run starts a container for the command and removes it afterwards.

appbay init-system

Bootstrap a fresh host to run Appbay: installs the container runtime and sets up ownership and access for the Appbay tree. Written for RHEL-family hosts, where the defaults differ enough to matter.

sudo appbay init-system                     # --owner service (default)
sudo appbay init-system --owner operator

--owner service creates a no-login system service account, which is the right choice for a homelab or worklab box. --owner operator uses your own account instead.

appbay init

Scaffold the $APPBAY_HOME directory structure and seed system app definitions.

appbay init
appbay init --dir /opt/appbay
appbay init --project homelab --domain homelab.example.com --yes
Flag Default Description
--dir <path> ~/.appbay Override $APPBAY_HOME location — persisted, see below
--project <name> (prompted) Name of the default project
--domain <name> (prompted) Base domain for ingress routing
--yes false Non-interactive: accept all defaults

Creates: etc/apps/, etc/projects/, etc/presets/, var/lib/renders/, var/lib/state/, var/log/. Seeds system app definitions if absent.

Warning--dir changes where every later command looks

--dir is not scoped to this one run: it writes the path to ~/.config/appbay/home, so every subsequent appbay invocation on this account resolves there until you change it. Undo it with appbay home clear, or repoint with appbay home set <path>.

To initialise a throwaway install without touching that default — what a test or a journey script wants — set the environment variable instead, which init honours as a runtime override and deliberately does not persist:

APPBAY_HOME=/tmp/scratch/home appbay init --project t --domain t.local --yes

Exit codes: 0 = success, 1 = filesystem error.

appbay server start

Start the Appbay server as a Docker Compose stack.

appbay server start
appbay server start --open
Flag Default Description
--open false Open the web UI in a browser after start

Creates appbay_shared network, starts the appbay-server container, waits for health check, prints the server URL.

Exit codes: 0 = server healthy, 1 = start failed, 2 = health check timeout.

appbay server stop

Stop the server container.

appbay server stop

Exit codes: 0 = stopped, 1 = error.

appbay server status

Check whether the Appbay server is running. Prints the server URL and start time if running, or a “not running” message if it is not.

appbay server status

Exit codes: 0 = always (status is informational).

appbay up

Deploy one or more apps.

appbay up jellyfin
appbay up ollama webui tts
appbay up --collection ai-stack
appbay up --all
Flag Default Description
--collection <name> (none) Deploy all apps in a collection
--all false Deploy all discovered apps

Runs the full pipeline: compile, apply overlays, write renders, and bring up via docker compose up -d.

Exit codes: 0 = deployed, 1 = compile or deploy error.

appbay apply

Compile and review a plan, then deploy with explicit confirmation. Separates compile and deploy for review workflows.

appbay apply --all --yes
Flag Default Description
--dry-run false Show the plan without applying
--yes false Skip confirmation prompt and deploy immediately
--all false Apply all discovered apps

Exit codes: 0 = applied (or dry run complete), 1 = compile or deploy error.

Flag Default Description
--all false Stop all discovered apps

Exit codes: 0 = stopped, 1 = error.

appbay delete

Remove an app definition and stop its containers.

appbay delete myapp --keep-volumes --force
Flag Default Description
--keep-volumes false Keep Docker volumes after deletion
--force false Skip confirmation prompt (required to proceed)

Without --force, the command exits with an error and instructions. Runs docker compose down (with -v unless --keep-volumes) before removing the app definition directory.

Exit codes: 0 = deleted, 1 = not found or confirmation required.

appbay status

Show app configuration and metadata. Available offline.

Flag Description
--json Output as JSON

Without an app name, shows a summary table of all discovered apps (name, services count, traits count, errors). With an app name, shows full detail: directory, project, environment, services (with service-level traits), app-level traits, overlays, and upstream configuration.

appbay secrets init

Initialize the local secrets vault. Auto-generates a master password if none provided.

appbay secrets init
appbay secrets init --password mypassword

appbay secrets set

Store a secret in the vault. Key format: KEY for default scope, APP/KEY for app-scoped.

appbay secrets set DB_PASSWORD myvalue
appbay secrets set kestra/DB_PASSWORD myvalue

Warns if the secret already exists, with database-specific guidance.

appbay secrets get

Retrieve a secret value from the vault.

appbay secrets get DB_PASSWORD
appbay secrets get kestra/DB_PASSWORD

appbay secrets delete

Delete a secret from the vault.

appbay secrets delete DB_PASSWORD
appbay secrets delete kestra/DB_PASSWORD

appbay secrets vault

List all secrets stored in the vault, grouped by scope. Shows metadata only — never values.

appbay secrets vault
appbay secrets vault --scope kestra

appbay secrets scan

Discover secret-like env vars in an app’s compose and .env files. Suggests vault URI mappings for unmanaged secrets.

appbay secrets scan kestra

appbay secrets import

Scan an app and auto-create vault entries for unmanaged secret-like variables.

appbay secrets import kestra
appbay secrets import kestra --dry-run

Verify that all secret URI references across all apps can be resolved.

appbay secrets check

List secret URI references for an app (or all apps). Prints URIs only — never values.

appbay admin — retired

RFC-001 §1 removed AppBay’s own accounts. The control plane is a stack behind the Caddy Security edge like any other app, so the account that signs in to AppBay is an edge user:

appbay edge users reset-password alice --generate --reveal

Running appbay admin prints this and exits non-zero, so a script that still calls it fails rather than appearing to succeed.

ImportantOne store now, and a role instead of a second password

There is no longer a separate credential domain for the control plane. What distinguishes it is the role: its edge route carries an admin-only policy (authp/admin), narrower than an app’s default, because it is the one stack that can reach the container runtime socket. So “can open Grafana” still does not imply “can reconfigure the installation”.

appbay list

List all discovered apps. Available offline.

appbay list
appbay list --json
Flag Description
--all Include apps with discovery errors (default: all apps shown anyway)
--json Output as JSON array

Reads from $APPBAY_HOME/etc/apps/ and shows each app’s name, project, environment, whether an appbay.yaml exists, and the compose filename. Does not require Docker or the server to be running.

appbay ps

Show container runtime status for apps. Runs docker compose ps against rendered compose files.

appbay ps
appbay ps jellyfin
appbay ps jellyfin redis
appbay ps --json
Flag Default Description
--all false Include apps without rendered compose files
--json false Output as JSON

Prefers the rendered compose file in var/lib/renders/; falls back to the source compose.

Exit codes: 0 = success, 1 = docker compose failed or no apps found.

appbay config

Get or set configuration values in an app’s appbay.yaml. Uses dot-separated key paths.

appbay config jellyfin                          # show all config
appbay config jellyfin upstream.source          # read a single key
appbay config jellyfin upstream.source my-app  # set a value

Values are auto-coerced: "true" → boolean, "42" → number, everything else stays string.

Exit codes: 0 = success, 1 = app or key not found.

appbay env

Manage environment variables in an app’s .env file ($APPBAY_HOME/etc/apps/<app>/.env).

appbay env jellyfin               # list all variables
appbay env jellyfin DB_HOST       # get a variable
appbay env jellyfin DB_HOST db    # set a variable
appbay env jellyfin DB_HOST --delete  # delete a variable
Flag Default Description
--list false List all variables
--delete false Delete the specified variable

Exit codes: 0 = success, 1 = app not found or key not found.

appbay presets

Manage named app selection presets. Presets save which apps are selected together for quick recall. Stored as YAML in $APPBAY_HOME/etc/presets/.

appbay presets save ai-dev --apps "ollama,webui,whisper"
appbay presets load ai-dev
appbay presets list
appbay presets delete ai-dev

appbay presets save <name>

Flag Description
--apps <list> Comma-separated app names to include
--description <desc> Optional description

appbay presets load <name>

Prints the app list from the preset. Typically piped to appbay up:

appbay up $(appbay presets load ai-dev)

appbay presets list

List all saved presets with their app lists.

appbay presets delete <name>

Delete a preset by name.

appbay home

Print, explain or repoint the resolved $APPBAY_HOME path.

appbay home                  # print the resolved path, and nothing else
appbay home --explain        # show every tier and which one wins
appbay home set <path>       # persist a new home for future commands
appbay home clear            # forget the persisted home

Bare appbay home prints only the path, so cd $(appbay home)/etc/apps keeps working.

Resolution order — the first tier with a value wins:

# Tier Set by
1 $APPBAY_HOME the environment; a runtime override that always wins
2 /etc/appbay/config appbay init-system (a host-level decision) — holds home: and nothing else
3 ~/.config/appbay/home appbay init --dir, or appbay home set
4 ~/.appbay built-in default
NoteWhy tier 2 is a file and not a systemd unit

RFC-001 proposed replacing it with Environment=APPBAY_HOME= in a unit. Measured on a real host, a unit’s environment reaches the processes systemd starts and nothing else: the service saw the home, an operator’s login shell saw nothing. Tier 2 serves that second case — an operator typing appbay … — which is precisely where a per-operator ~/.config/appbay/home would otherwise win. Deleting it made the CLI resolve a personal path over a service install.

--explain prints all four with the winner marked, and warns when the resolved path does not exist, has no etc/ (never initialised), or is a saved pointer under a temp directory that will not survive a reboot.

set writes tier 3 and refuses when tier 1 or 2 would shadow it — a saved path that a higher tier overrides is a setting that reports success and changes nothing. It also refuses a path that does not exist. --force overrides both refusals; when forced past a shadowing tier it says so rather than claiming the resolved home changed.

clear removes tier 3 and reports the tier now in force. Use it to undo an appbay init --dir that pointed at a directory you no longer want — including a throwaway one that has since been deleted.

Exit codes: 0 = printed, explained, set or cleared; 1 = set refused (shadowed by a higher tier, or the path is missing or not a directory).

appbay fixfs

--gid <n> Grant access to a specific GID
--dry-run Show what would change without applying

Exit codes: 0 = success.

Public tunnels

appbay tunnel

Create a Cloudflare quick tunnel exposing a local app publicly, without touching your edge or DNS.

appbay tunnel jellyfin
appbay tunnel jellyfin --port 8096
Flag Description
--port <port> Override the port to tunnel
WarningA quick tunnel is public and unauthenticated

It publishes the app on a Cloudflare-generated hostname that anyone with the URL can reach. It does not pass through the Caddy Security edge, so an auth trait on the app does not apply to traffic arriving this way. Use it for a demo or a temporary share, not as a way to publish something permanently.

appbay tunnel-down

Stop all running Cloudflare tunnels.

appbay tunnel-down

Retired commands

appbay auth and appbay authelia still exist as stubs that exit non-zero. They print what replaced them and change nothing.

Authelia was AppBay’s authentication edge until S25 replaced it with the integrated Caddy Security edge. appbay admin joined them when RFC-001 §1 removed AppBay’s own accounts. Authentication now lives entirely in appbay edge — one store for the people who sign in to your deployed apps and to AppBay itself.
