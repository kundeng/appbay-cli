User Guide

Learn how to use Appbay to manage your Docker apps

What is Appbay?

Appbay is a Docker-native PaaS control plane that treats Docker Compose as the application model. Rather than replacing Compose or inventing a new orchestration layer, Appbay augments your existing Compose files with traits, scoped variables, conditional overlays, secrets management, and namespace isolation – all while keeping standard docker compose as the runtime contract.

You can eject any app at any time and run it with plain docker compose up. Appbay adds structure; it never locks you in.

Who is Appbay for?

Appbay serves three overlapping use cases:

Homelab
You host upstream applications (Jellyfin, Nextcloud, Vaultwarden) with minimal friction. You want ingress routing, TLS certificates, and forward authentication without hand-editing Traefik labels for every app.
Applab
You run curated application stacks for a team or department. You need consistent environments, secret management, and the ability to deploy a named collection of apps with one command.
Devlab
You build applications that require extensive configuration, iteration, and environment-specific wiring. You need scoped variables, conditional cross-app wiring, and deterministic renders so that the same inputs always produce the same outputs.

Design principles

Before diving in, these principles shape every feature in Appbay:

  • Filesystem is the source of truth. Your appbay.yaml and docker-compose.yml files on disk are authoritative. SQLite is a metadata cache that can be rebuilt at any time with appbay rebuild-cache.
  • Deterministic renders. Same inputs always produce the same outputs. Generated values are stored once and reused.
  • Secrets never leak. No plaintext secrets appear in logs, rendered artifacts, plan diffs, or events.
  • CLI works without the web frontend. Validate, compile, deploy, and eject all work with no server container running.
  • Standard Compose output. Everything Appbay produces is runnable with docker compose directly.
